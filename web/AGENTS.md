# AGENTS.md — Nexata Web Frontend

Guidelines for AI agents working on the Nexata web codebase.

## Important Guidelines

- **Do not commit changes** unless explicitly requested. The git diff is used by developers to review changes.
- **Do not modify `src/paraglide/`** — these files are auto-generated by the Paraglide i18n plugin.
- **Do not modify `src/routeTree.gen.ts`** — auto-generated by TanStack Router plugin.
- **Do not modify `src/components/ui/`** files unless fixing a bug — these are shadcn/ui components managed via the `shadcn` CLI.

## Stack Overview

- **Framework**: React 18.2 SPA (NOT Next.js) with Vite 7
- **Routing**: TanStack Router (file-based, auto code-splitting)
- **Data Fetching**: TanStack React Query
- **State Management**: Zustand (persisted stores), TanStack Query (server state)
- **Styling**: Tailwind CSS v4 + shadcn/ui (base-nova style) + CSS variables (oklch)
- **API Client**: ElysiaJS Eden Treaty (type-safe, mirrors backend routes)
- **i18n**: Paraglide (inlang) — base locale is Spanish (`es`), with English (`en`)
- **Package Manager**: Bun

### Testing

No test framework is currently configured. There are no test scripts in `package.json`.

### Linting / Formatting

No ESLint, Biome, or Prettier config exists. The project relies on TypeScript strict mode
for static analysis. Key compiler flags in `tsconfig.app.json`:

- `strict: true`
- `noUnusedLocals: true`
- `noUnusedParameters: true`
- `noUncheckedIndexedAccess: true`
- `noFallthroughCasesInSwitch: true`
- `verbatimModuleSyntax: true` — requires explicit `type` keyword on type-only imports

Run `bun tsc -b` to verify your changes compile cleanly.

## Code Style

### Formatting Conventions

- **Indentation**: Tabs in `src/lib/` and `src/routes/`; 2-space in `src/components/` and `src/hooks/`
- **Quotes**: Single quotes in `src/lib/` and `src/routes/`; double quotes in `src/components/` and `src/hooks/`
- **Semicolons**: Always use semicolons
- **Trailing commas**: Use trailing commas in multi-line constructs

When editing an existing file, match the formatting style already used in that file.

### Import Order

Imports are not auto-sorted. Follow the general convention:

1. External packages (`react`, `@tanstack/*`, `framer-motion`, etc.)
2. Internal aliased imports (`@/lib/*`, `@/components/*`, `@/hooks/*`)
3. Relative imports (`./sibling`, `../parent`)

Use `import type { ... }` or `import { type Foo }` for type-only imports
(required by `verbatimModuleSyntax`).

### Types

- Prefer `type` over `interface` (except for module augmentation)
- Derive types from API functions using `Awaited<ReturnType<typeof fn>>`
- Use indexed access for sub-types: `Me['language']`, `CredentialsResponse[number]`
- Inline props for simple sub-components; use separate `type FooProps = { ... }` for 3+ props

```typescript
// Deriving types from API functions (standard pattern)
export type Me = Awaited<ReturnType<typeof getMe>>;
export type Language = Me['language'];
export type CredentialItem = CredentialsResponse[number];
```

### Components

- Use **function declarations** (not arrow functions): `export default function Sidebar()`
- Page/feature components use `export default function`
- Shared utility components use named exports: `export function TenantLogo()`
- Props are typed inline or via a separate `type` alias

### Route Definitions (TanStack Router)

Every route file in `src/routes/` exports a `Route` constant:

```typescript
export const Route = createFileRoute('/_private/chat')({
  component: NexataChat,
});
```

- `_private/` prefix = authenticated layout group (wraps with Sidebar)
- `_public/` prefix = unauthenticated layout group
- Auth guard uses `beforeLoad` + `throw redirect(...)` pattern
- Navigate with `useNavigate()` hook: `navigate({ to: '/chat' })`

### API Calls (Eden Treaty)

All API calls go through `withAuthRetry` which handles 401 → token refresh → retry:

```typescript
export async function getMe() {
  return await withAuthRetry((headers) =>
    apiClient.user.me.info.get({ $headers: headers }),
  );
}
```

- Pass headers via `$headers`, query params via `$query`, body fields spread directly
- Use `!` for dynamic route segments: `apiClient.chat.thread[threadId]!.get(...)`

### Data Fetching Hooks

Data-fetching hooks live in `src/lib/` (NOT `src/hooks/`), co-located with their API functions:

```typescript
// Query hook
export function useMe() {
  return useQuery<Me>({ queryKey: ['me'], queryFn: getMe, staleTime: Infinity });
}

// Mutation hook — returns an async function, NOT useMutation
export function useDeleteThreadById() {
  const queryClient = useQueryClient();
  return async (threadId: string) => {
    await deleteThreadById(threadId);
    await queryClient.invalidateQueries({ queryKey: ['chat-threads'] });
  };
}
```

- Query keys: string arrays like `['me']`, `['chat-thread', threadId]`, `['admin', 'users']`
- Mutation hooks return plain async functions and invalidate queries on success
- Errors propagate to callers (no error handling inside mutation hooks)

### UI-Focused Hooks

UI hooks live in `src/hooks/` and handle browser/DOM concerns:
`use-auto-scroll.ts`, `use-copy-to-clipboard.ts`, `use-toast.ts`, etc.

### Error Handling

- API errors are handled by `withAuthRetry` (auto-refresh on 401, force logout on failure)
- Use the 3-phase toast pattern for user-facing operations:

```typescript
const toastId = infoToast.loading({ title: 'Deleting...' });
try {
  await deleteItem(id);
  infoToast.success(toastId, { title: 'Deleted' });
} catch (error) {
  infoToast.error(toastId, { title: 'Failed to delete' });
}
```

### i18n (Paraglide)

Translation messages are imported from `@/paraglide/messages.js` and called as functions:

```typescript
import { "sidebar.new_chat" as sidebar_new_chat } from "@/paraglide/messages.js";
// Usage: sidebar_new_chat()
// With params: sidebar_delete_desc({ title: chatTitle })
```

Translation files: `messages/es.json` (base), `messages/en.json`.

### Zustand Stores

Stores use the `create` function with optional `persist` middleware:

```typescript
export const useChatUIStore = create<ChatUIState>()(
  persist(
    (set) => ({
      activeThreadId: null,
      startNewChat: () => set({ activeThreadId: null, status: 'new' }),
      // actions co-located with state
    }),
    { name: 'chat-ui-store', partialize: (state) => ({ activeThreadId: state.activeThreadId }) },
  ),
);
```

Access via hook selectors: `useChatUIStore((s) => s.activeThreadId)`
Or direct access outside React: `useChatUIStore.getState().startNewChat()`

